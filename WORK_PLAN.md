## 1. Краткое резюме для руководства

Платформа ENT Prep (веб-приложение для подготовки к Единому национальному тестированию) сейчас находится в стадии **работающего MVP**. Реализован базовый цикл: регистрация ученика → прохождение теста → просмотр результата. В базе — **34 286 вопросов по 15 предметам**.

Дальнейшее развитие направлено на три стратегические цели:

1. **Соответствие реальному формату ЕНТ 2026** (сейчас используется упрощённый формат «10 вопросов / 10 минут», что не отражает экзамен).
2. **Интеграция авторских материалов учебного центра** — тесты из Google Forms с графиками, схемами и формулами.
3. **AI-аналитика и персонализация** — автоматический разбор ошибок ученика, прогноз балла, персональный план подготовки.

Работа разделена на **3 этапа общей продолжительностью ~9 месяцев**. План построен с учётом имеющихся ресурсов и рекомендаций по архитектуре.

## 3. Что не сделано (ключевые пробелы)

Эти пробелы определяют приоритеты плана. Перечислены в порядке критичности:

1. ❌ **Формат тестирования не соответствует ЕНТ 2026.** Реальный экзамен — 5 предметов, 120 вопросов, 4 часа. Сейчас — 10 вопросов, без таймера.
2. ❌ **Нет вопросов с картинками.** Графики, схемы, чертежи, формулы — обязательная часть ЕНТ по физике, математике, химии, биологии. Текущая база не поддерживает их адекватное хранение и отображение.
3. ❌ **Авторские материалы не интегрированы.** Готовые тесты из Google Forms не загружены в платформу.
4. ❌ **Нет разделения источников вопросов.** Невозможно отличить проверенные авторские вопросы от собранных из внешних источников.
5. ❌ **Нет AI-разбора ошибок.** Ученик видит правильный ответ, но не получает объяснения.
6. ❌ **Нет прогноза балла ЕНТ** и рекомендаций по подготовке.
7. ⚠️ **Безопасность не готова к продуктивной эксплуатации** (`DEBUG=True`, секретные ключи в коде).
8. ⚠️ **База данных на SQLite** — не масштабируется при росте числа пользователей.

## 4. Архитектурные решения (согласованы)

Приняты следующие технологические и архитектурные решения:

| Решение | Обоснование |
|---|---|
| **Стек: Django + DRF** (без замены на FastAPI) | Уже работает, есть готовый админ-интерфейс, ускоряет разработку. Сервер 4 ГБ RAM / 2 vCPU справится. |
| **База данных: PostgreSQL** | Замена SQLite перед запуском на сервер. PostgreSQL стабильнее при параллельной работе и тяжёлых запросах аналитики. |
| **Хранение картинок: локально на сервере** | NVMe 100 ГБ достаточно для ~500 000 изображений. Nginx отдаёт напрямую — экономия ресурсов. Переход на облачное S3-хранилище возможен позже без переписывания кода. |
| **Две категории контента** | Авторские вопросы (`source_type = authorial`) и собранные (`collected`). У каждой — свой статус верификации. |
| **Модель симуляции ЕНТ** | Отдельная сущность `EntExamSession` объединяет 5 предметных сессий в единый экзамен. Чистая структура, лёгкий подсчёт итогового балла. |
| **Импорт из Google Forms** | Через Django management-команду, запускается вручную или по расписанию. Избегает сложного UI, но автоматизирует загрузку. |

## 5. Детальный план работ

### ЭТАП 1 — ФУНДАМЕНТ (Месяцы 1–3)

Цель: привести платформу в соответствие формату ЕНТ 2026, интегрировать авторский контент, подготовить к продуктивному запуску.

#### 1.1. Расширение модели данных (Недели 1–3)

**Задачи:**
- Добавить в модель `Subject` поля формата ЕНТ 2026:
  - `subject_type` (обязательный / профильный)
  - `question_count` (20 / 10 / 10 / 40 по типу предмета)
  - `time_minutes`, `max_score`
  - `is_visible` (видимость для учеников), `sort_order`, `language`
- Добавить в модель `Question` поля происхождения и верификации:
  - `source_type` (authorial / collected)
  - `verification_status` (draft / verified / rejected)
  - `language`, `year`, `external_id` (для дедупликации при импорте)
  - `ai_explanation` (под AI-разбор, закладываем на будущее)
- Создать новую модель `EntExamSession` для симуляции полного экзамена
- Написать и применить миграции базы данных

**Результат:** база данных поддерживает реальный формат ЕНТ, разделение источников, готова к импорту авторских материалов.

#### 1.2. Конвейер импорта авторских материалов из Google Forms (Недели 3–6)

**Задачи:**
- Разработать Django management-команду `import_from_google_forms`
- Настроить доступ к Google Drive API для загрузки изображений
- Реализовать парсинг структуры Google Form (вопрос, варианты ответов, правильный ответ, картинка в теле вопроса)
- Сохранение изображений в локальное хранилище
- Защита от дубликатов при повторном импорте (по `external_id`)
- Все импортированные вопросы маркируются `source_type = authorial`, `verification_status = verified`
- Загрузить первую партию тестов учебного центра

**Результат:** авторские тесты с графиками и схемами доступны в платформе. Процесс повторяемый — новые тесты добавляются одной командой.

#### 1.3. Три режима тестирования (Недели 5–8)

**Задачи:**
- **Тренировка** — короткий тест, без таймера, с мгновенным разбором (текущий режим)
- **Тематический** — вопросы по выбранной теме, количество настраивается
- **Полная симуляция ЕНТ** — 5 предметов, 120 вопросов, 4 часа, точный формат экзамена
- Переработать экраны фронтенда под выбор режима
- Реализовать серверный таймер для симуляции

**Результат:** ученик может тренироваться в формате, максимально близком к реальному экзамену.

#### 1.4. Подготовка к продуктивному запуску (Недели 7–10)

**Задачи:**
- Миграция базы данных с SQLite на PostgreSQL
- Безопасные продакшн-настройки:
  - `DEBUG = False`
  - Явный список `ALLOWED_HOSTS`
  - Секретные ключи — только через переменные окружения (`.env`), убрать из кода
- Настройка Nginx для отдачи изображений напрямую
- Резервное копирование базы данных (ежедневное)
- Базовый мониторинг ошибок (Sentry или аналог)
- Деплой на выделенный сервер (4 ГБ RAM / 2 vCPU / 100 ГБ NVMe)

**Результат:** платформа готова к работе с реальными учениками в защищённом режиме.

#### 1.5. Управление видимостью предметов (Неделя 8–9)

**Задачи:**
- Реализовать фильтрацию: ученики видят только предметы с `is_visible = True`
- Добавить в кабинет учителя/администратора переключатель вкл/выкл для каждого предмета
- Скрыть предметы с недостаточной базой вопросов (например, «Казахская литература» — 232 вопроса)

**Результат:** контроль над тем, какие предметы доступны ученикам.

### ЭТАП 2 — РОСТ (Месяцы 4–6)

Цель: AI-функционал, персонализация, прогнозирование результата.

#### 2.1. AI-разбор ошибок через Google Gemini (Недели 11–15)

- Подключение Gemini API (модель `gemini-1.5-flash` — оптимально по цене и качеству, поддерживает анализ изображений)
- Эндпоинт `/api/ai/explain/` — объяснение, почему ответ ученика неверен и почему правильный верен
- Кеширование объяснений в базе данных (один вопрос объясняется один раз)
- Поддержка русского и казахского языков
- Ограничение: не более 20 AI-запросов на ученика в день (контроль расходов)
- Важно: для вопросов с картинками используется **мультимодальный** режим Gemini (анализ изображения)

#### 2.2. Определение слабых тем и персональный план (Недели 14–18)

- На дашборде ученика — блок «Слабые темы» (процент правильных ответов ниже 50%)
- Кнопка «Потренировать слабые темы» — запуск теста только по этим темам
- Персональный план подготовки: ученик указывает дату экзамена и целевой балл → платформа строит график подготовки

#### 2.3. Прогноз балла ЕНТ (Недели 17–20)

- Блок «Прогноз» на дашборде с динамикой (растёт / стабильно / падает)
- Прогноз рассчитывается по реальной шкале ЕНТ (профильные предметы считаются из 50, не линейно)
- Калькулятор доступных специальностей и грантов при текущем прогнозируемом балле

#### 2.4. Кабинет администратора (Недели 16–22)

- Управление пользователями (список, роли, блокировки)
- Управление группами учеников (класс, школа, смена)
- CRUD предметов, тем, вопросов
- Системные настройки (название организации, пороговые баллы)

### ЭТАП 3 — ЗРЕЛОСТЬ (Месяцы 7–9)

Цель: отчётность для родителей и школ, геймификация для вовлечённости.

#### 3.1. Аналитика прогресса + экспорт PDF (Недели 23–28)

- Страница «Прогресс» для ученика: графики по предметам, динамика по темам, серии дней подряд
- Экспорт PDF-отчёта для родителей и учителей (`api/reports/student/{id}/pdf/`)
- Содержимое: итоговая таблица баллов, графики, слабые/сильные темы, рекомендации
- Рендеринг через ReportLab (надёжнее на сервере, чем WeasyPrint)

#### 3.2. Геймификация (Недели 26–34)

- **Question Rush** — гонка на время (30 вопросов за 5 минут)
- **Дуэли между учениками** (асинхронный режим — без realtime-сервера)
- Система очков и достижений: «Первый тест», «Серия 7 дней», «100% по теме», «Победа в дуэли»

## 8. Риски и меры по снижению

| Риск | Вероятность | Влияние | Меры по снижению |
|---|---|---|---|
| **Качество импортированных вопросов** из Google Forms может требовать вычитки | Средняя | Среднее | Все вопросы помечаются `verified` только после проверки учителем. Статус `draft` по умолчанию. |
| **Нехватка RAM (4 ГБ)** при тяжёлых аналитических запросах (отчёты, дашборды) | Средняя | Высокое | Оптимизация запросов, индексы БД, при необходимости — read-replica для аналитики. |
| **Квота Gemini API** может исчерпаться при росте числа учеников | Высокая | Среднее | Жёсткое rate limiting (20 запросов/день/ученик), кеширование объяснений в БД. |
| **Объём базы изображений** растёт быстрее расчётного | Низкая | Низкое | 100 ГБ NVMe достаточно для ~500 000 изображений. Запас — 2–3 года. Переход на S3 возможен без переписывания кода. |
| **Сроки разработки** могут сместиться из-за сложности интеграции с Google API | Средняя | Среднее | Этап 1.2 заложен с запасом. При задержке — fallback на ручной экспорт из Google Sheets/Excel. |
| **Переход SQLite → PostgreSQL** может выявить скрытые проблемы | Низкая | Среднее | Настройки `DATABASE_URL` уже заложены. Перенос через `dumpdata`/`loaddata`. |
